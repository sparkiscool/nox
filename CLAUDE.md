# Nox

Spark's drone project: the **box** (funnel, hook latch, swap arm, bays, stand), **Scout v3** (`nox/scout/v3/`) and the **Overseer** (`nox/overseer/`). This repo is the only source: nothing depends on a file that exists only on a PC, in a chat or in an artifact.

## Every session
1. `git pull` on `main`. Read only your part's row in `nox/current-parts.md`, its part doc and the `nox/dimensions.md` section it uses (`python3 tools/dim.py <section>`, never the whole file).
2. Branch `part/<part>` for design work, `run/<part>-<version>` for a heavy run (one `run-part` worker per run; several run at once). One prompt from brief to saved part: `/part <part> <version>: <brief>`.
3. Every turn that changes a design commits and pushes the same turn: script, results, the part's row, one line at the top of `nox/log.md` (≤ 400 chars: what changed and where; the detail lives in the part doc and `summary.md`). Unpushed work does not exist.
4. End with a small PR to `main`, one part. First `python3 tools/check_state.py` (no ERROR; fix the warnings your rows or lines caused). Then `python3 tools/pr.py open "<part> <version>: <what>" [body.md]`. CI (`.github/workflows/checks.yml`) must be green before merge; `tools/pr.py merge` refuses otherwise. Run the `review` agent on it; on PASS merge it yourself, `python3 tools/pr.py merge <n>`; on FAIL fix and re-review, never merge a FAIL. A tooling, docs, config or research PR is merged after the session's own check. A refused merge means main moved: merge `origin/main` into the branch, resolve, push, merge again. No PR waits on Spark.
5. A system session owns every piece cut from its system (one PR may carry them). Never edit a part outside it, its script or row; put what it must change in the PR description and say which part you kept.
6. A rule change (Spark) lands in one PR: one line in Hard rules, the method in `docs/generative.md`, and its check (a tool, or a `review` check). Skills and agents point at those and never restate a rule.

## Hard rules (Spark)
- **Solid check gates everything.** Nothing is saved, called BUILT or READY, or shown unless `python3 nox/solid_check.py <mesh>` reads PASS on the exact file. A FAIL is fixed in the design, never on the mesh. Every other check is reported, never blocks.
- **Attachments are drawn**, never generated: pads ≥ Ø12 with ≥ 2.0 web, posts ≥ 6 x 6, a gusset into the body, a boss wall ≥ 3 round every counterbore or access cut.
- **Tag every number:** P measured, M mesh, C CAD, E estimate, F frame model. A number lives only in `nox/dimensions.md`.
- **Ready to print = a picture and a slicing prompt (picture: Spark 24 Oct).** Every reply that says a file is ready to print shows a picture of each print file and ends with the laptop slicing-session prompt (`docs/generative.md`, Save and print), filled in, in a code block.
- **Every idea comes with a visual (Spark 24 Oct).** Any design, option, concept or change shown to Spark comes with a picture of it (a published artifact: layout, section, sequence or wiring diagram, motion or render), linked in the same reply; never words and numbers alone (`docs/generative.md` The rule, 0, Visuals).
- **PETG rigid, cage nodes included (Spark 27 Oct: stiffer joints, epoxy holds); TPU only for feet, skids and strips; no PLA.** Nothing under 2.0 mm (flexures excepted). Rods 3.0 carbon wherever one passes, thicker solid or tube carbon only where the system's frame model needs it (Spark 24 Oct), epoxied, socket bore from the coupon pick (DEFAULT 6.1 / 3.1, Spark 27 Oct: OD + 0.3 was loose). Bambu A1 mini, 180 cube, tree supports, largest flat face down.
- **No old designs** (slide swap, slider, pusher, turret, turntable, carousel, groove seat, Z stage, top-mounted battery) unless Spark asks fresh. Simplest design wins; every placement comes from an optimization.
- **System first, then cut (Spark 24 Oct).** Never design or optimise a part alone: a system pass on the assembled thing (every part and bought part in pose, flight / crash / swap / handling cases, load path through every joint, the cuts) writes each piece's requirements to `dimensions.md` "System <name>"; each piece then runs its own topology with those as parameters; the assembled result is rechecked. Holds for every READY, BUILT, HOLD and DESIGN part. Method: `docs/generative.md` The rule, 0.
- **Every drone design, in this order (Spark 24 Oct).** Checked on the assembled model (`nox/system_check.py`); numbers in `dimensions.md` L; method for each item in `docs/generative.md` The rule, 0.
  1. **Light, never at the cost of the design.** Topology on real loads, as light as it can be while every target below holds. Weight is a soft target: reported, never a gate; the design wins and the summary says what extra grams buy.
  2. **Compact and organised.** Parts nest round the load path, never stacked with filler between; nothing wastes space; everything that must be reached is reachable without taking another part off.
  3. **Cage first.** Whatever the drone hits, a cage member touches first, ≥ 3 mm ahead (DEFAULT) of props, motors, electronics, camera, lidar and pack; full cage top, sides, bottom, triangulated into the core. A field sensor outside the cage (Geodesic cage line) is held to this outside its field cone. No stick or column layout is shown as a design.
  4. **Balanced.** CG on the thrust centre within 3 mm (DEFAULT), pack in and pack out.
  5. **Mounted for what it carries.** Each piece's topology is loaded from the system: real supports, carried masses at their CG, joint reactions. A heavy one-sided payload (the L2) gets the full moment and a braced path into the core, never a stalk.
  6. **Stiff where it senses** (DEFAULT): FC, camera and lidar mounts ≥ 100 Hz.
  7. **Breaks in the right order** (DEFAULT): a cheap cage node or foot fails first and is replaced without taking the drone apart.
  8. **Clear air, clear view, clean wiring** (DEFAULT): only arms and thin rods in the prop wash or the sensor views; every cable routed, strain-relieved, unpluggable; heat sources in airflow.
  9. **Fits the box:** funnel catch, hook latch zone and swap path are in every drone's system model.
- **Cages are geodesic shells formed to the drone (Spark 26 Oct, the Elios 3 photo).** Every drone cage is a closed triangulated (geodesic-pattern) shell of large cells (frequency 2) of 6 mm carbon tubes on printed nodes, wrapped round the drone's own layout as tight as it goes (not a sphere; usually a disk): props, motors, pack and electronics inside; a sensor that needs a clear field (the L2, the cameras) sits outside it with nothing of the drone in its view, supported and guarded only from behind its view (Spark 26 Oct); one bottom opening clears the receiver + 30 a side for the swap. Perfect left-right mirror symmetry, nodes and tubes (nose and tail may differ); no tube-length limit; only 6 mm and 3 mm tubes (Spark 27 Oct). The box funnel is designed round the cage, never the cage round the funnel. Method `docs/generative.md` The rule, 0 (Geodesic cage); check `system_check` shell (closed, mirror) and field openings.
- **Carbon where its length earns it (Spark 24 Oct).** A cage member shorter than the break-even length (DEFAULT 33 mm: a 3.0 rod plus its two sockets weighs the same as a 6 x 6 PETG strut there), or one that only links printed parts close together, is printed into the node or mount, never carbon; every carbon rod's length is justified in the summary (method `docs/generative.md` The rule, 0).
- **Concept before detail; three strikes (24 Oct, DEFAULT).** No topology run or detailed CAD before the concept check (`docs/generative.md` The rule, 0): the system layout with the rule checks run on it, two alternatives weighed, the `review` agent in concept mode, the layout artifact and one line to Spark (then continue, never wait). A part whose third version in a row fails the gate, a check or Spark's look goes back to its system pass, never to a fourth patch.
- **Parallel by default (Spark 24 Oct).** Independent work never queues: separate workers at once (Agent tool, `isolation: "worktree"` for anything that commits; `create_session` when this box is full), each on its own branch and PR. Only a real dependency waits. A check, test or smoke run is never a dependency: every run of a system's pieces, variants and checks starts in the same turn, a full run its check fails is stopped, and a full box means a sibling session at once, never a queue (Spark 27 Oct; `docs/generative.md` Heavy runs; check `review_precheck` 12).
- **Children stay in sync by pull (Spark 24 Oct).** Children merge `origin/main` every step and pick up decisions, rules and numbers there; a controller messages a live child only when a change hits that child's own inputs or task (a Spark decision on it, a stop or supersede), one message per turn, priority later; finished children are archived (`docs/sessions.md`).
- **One task, one session; quiet workers (Spark 24 Oct).** The session Spark starts for a task does it with Agent-tool workers inside it; a new cloud session only for a heavy run or a full box. No hub, no digests: a session messages Spark only when its task is done, a file is ready to print or a decision of his is needed (nothing else: no progress, starts or check-ins), and spends tokens only when needed (`docs/sessions.md`). Workers and child sessions never message Spark.
- **Small contexts (Spark 24 Oct).** Tokens go to design, not to carrying context: sessions compact at 300k (`.claude/settings.json`), loops run in workers, a heavy run wakes its starter once (`tools/run_bg.py`), every spawn names its model, sessions read slices, review starts with `tools/review_precheck.py` (method `docs/sessions.md` Usage).
- **Sessions end when their work does (Spark 24 Oct).** Done = PRs merged or closed, nothing unmerged or running; updates go only to live sessions. The organiser (every 6 h, `docs/organiser.md`) archives finished sessions and keeps the project tidy.
- **Never wait on Spark.** Decide, mark DEFAULT, write the choice and the alternative in one `log.md` line, continue; a shared number changes the same way (its `dimensions.md` row + the log line). Spark reverts what he disagrees with. A session never spends money (Spark orders from the cart link) or deletes work on `main` alone. Replies short, no em dashes.

## Model and effort
| Work | Model | Effort |
|---|---|---|
| Design or CAD session (`part/<part>`), the control conversation, the `review` agent | opus | high |
| Geometry or a fit that two opus turns could not solve | fable | high |
| Print and slicing session on the laptop (computer control) | opus | medium |
| Heavy run (`run-part` agent), research, docs, log and state edits | sonnet | medium |
Agents carry theirs in `.claude/agents/`; a session takes `.claude/settings.json`; a project thread is started with the model above (`claude --model <m> --effort <e>` locally). Never a weaker model than the row says.

## Where things are
- `README.md`: the start page for Spark: what is where, how to start each kind of session.
- `nox/current-parts.md`: every part's state, file and next step; open items and Spark questions.
- `nox/dimensions.md`: every number (section M: bought parts and mounting data). `nox/parts-list.md`: every bought and printed part with qty and status (on hand / ordered / to buy).
- `docs/sessions.md`: session lifecycle, tasks, workers and reporting, the sweep. `docs/organiser.md`: the 6 h organiser run.
- `docs/generative.md`: heavy runs, the generative rule, save and print, done = saved.
- `nox/topo/`: the topology engine, the default for every generated part (`from topo import Part, Settings, optimise`; organic finish; `nox/topo/README.md`). After an engine edit run `cd nox && python3 -m topo.test_topo` once.
- `nox/*.py`: the tools (`solid_check`, `print_orient`, `render_preview`, `motion`, `interfaces`, `system_check` (cage first, probes, access, fit, balance, mass), `assembly` (one `nox/<machine>/<system>.assembly.json` per system, `nox/ASSEMBLY.md`)); `tools/check_state.py` lints the state (`--branches`); `tools/dim.py` prints one `dimensions.md` section; `tools/run_bg.py` runs a heavy job to the end with checkpoint commits; `tools/review_precheck.py` is the review's mechanical half. `noxopt`, `noxopt_local`, `printopt`, `noxopt_demo` are the retired engine, kept for old part scripts only; no new part uses them.
- `nox/box/`, `nox/scout/v3/`, `nox/overseer/`: part docs and scripts. `runs/<part>/<version>/`: one folder per run, never overwritten; board `runs/index.md` (`python3 tools/runs_index.py`). `print/<part>_<version>.<ext>`: print files; the File cell in `current-parts.md` points at them.
- `tools/pr.py`: open and merge PRs over REST. `tools/amazon-parts-mcp/` + `.mcp.json`: Amazon ASINs, prices and cart links (skill `drone-parts`). `cloud/`: environment setup script and the SessionStart hook; start every cloud session in the "Nox" environment with this repo selected.
- `nox/log.md`, `nox/print-log.md`: history, newest first. `archive/`: Scout v2 and old queues, never a current design. `claude/`: background research; cite it when a task needs it, never read it by default.

## Git
- Commit messages: `<part> <version>: <what>` or `ckpt <n>`. Push after every commit. Never force-push `main`; never rewrite history on a shared branch.
- No git LFS (blocked from cloud boxes): any single file under 50 MB (decimate a viewing mesh, zip a big file); commit a run's final mesh, not every checkpoint's; a superseded run keeps summary, result and preview only (meshes recoverable from git).
- Cloud boxes block GitHub GraphQL: every `gh pr ...` subcommand fails with 403. `gh api repos/sparkiscool/nox/...` (REST) works; `tools/pr.py` wraps open and merge. Branch deletes are refused from cloud boxes; the repo's auto-delete removes merged branches.
- **A GitHub action a session cannot do** (branch deletes, repo settings, anything the proxy or the permission check refuses): give Spark one ready-to-paste prompt for Claude in Chrome in a code block (exact URLs, what to click, what to leave alone, what to check after), then carry on with the rest.
