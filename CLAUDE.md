# Nox

Spark's drone project: **Scout v2** (lightest caged quad, battery cartridge under the drone, contact pads) and the **box** (funnel, magnet hold, vertical swap wheel, two-head radial arm). Overseer is paused.

This repo is the only source. Docs, scripts, engine, run results and print files all live here. Nothing depends on a file that exists only on a PC, in a chat, or in an artifact. The full rule book is `nox/README.md`; read it only when a rule or a doc location is needed.

## Every session
1. `git pull` on `main` before anything else, then read only what the task needs: your part's row in `nox/v2/current-parts.md`, its part doc, the `nox/v2/dimensions.md` section it uses. Nothing else is a must-read.
2. Work on a branch: `part/<part>` for design work, `run/<part>-<version>` for a heavy run.
3. **Every turn that changes a design commits and pushes, same turn, no exceptions:** the script, the result files, the part's State / Version / Saved file cells in `current-parts.md`, one line at the top of `nox/v2/log.md`. Work that is not pushed does not exist; the next session cannot see it.
4. Finish by opening a PR to `main` (small, one part). Spark merges, or the Nox control conversation does.
5. Never edit another part's script or row. Write what it must change as one line in the PR description, and in the PR say which part you kept.

## Heavy runs (generative / topology / FE)
- One heavy run per session. The Nox control conversation starts one thread per run; a thread never waits on another.
- Run in the background, log to `runs/<part>/<version>/log.txt`, checkpoint every ~10 iterations, and **commit + push the checkpoint each time** (`git add runs/<part>/<version>; git commit -m "ckpt <n>"; git push`). A reclaimed VM keeps the branch, not the files.
- Report only the final numbers. Hard cap 6 h, then build from the last checkpoint.
- Peak memory: measure once at start (`/usr/bin/time -v` or `psutil`), tag it, and keep peak under 75 % of the machine. Runs above ~60k design cells use `noxopt_local` with `backend="gmg"`.
- Run cycle: `python3 nox/test_noxopt.py` once per session after any engine edit; never otherwise.

## Hard rules (Spark)
- **Speed first.** One blocking gate only: the solid check. Every other check is reported, never blocks.
- **Solid parts, no disconnected structures, ever.** Nothing is saved, called BUILT or READY, or shown as a result unless `python3 nox/solid_check.py <mesh>` reads PASS on the exact file (one body; one body after 0.9 mm erosion; every drawn feature inside it; no wall under 1.8 mm; neck test). A FAIL is fixed in the design, never patched on the mesh. Details: `nox/README.md` Rules.
- **Simplest design wins.** Fewer parts, features and steps; justify any added complexity.
- **Every placement comes from an optimization.** Nothing sits somewhere because it has to be somewhere.
- **Tag every number:** P measured, M mesh, C CAD, E estimate, F frame model.
- **Ask Spark** only on costly or hard-to-undo choices, or before changing a shared number. Otherwise decide, mark DEFAULT, continue. A question comes with its best answer in one line.
- **Replies short.** Each problem plainly, with the best fix. No em dashes.
- Everything we make is beautiful: the part, the preview, the summary, the doc.
- Drone parts: lightest that meets the loads. Box parts: strong and fits. PETG rigid, TPU nodes / feet, no PLA. Nothing thinner than 2.0 mm (flexures excepted). Rods epoxied.
- No old designs: never reintroduce a slide swap, slider, pusher, turret, turntable, carousel, groove seat, Z stage or top-mounted battery unless Spark asks fresh.
- Crash behaviour is proven by physical test. Buy and modify over building from scratch.

## Done = saved (automatic, same turn)
A part is finished only when, in one turn: (0) `solid_check` PASS on the exact file; (1) `print_orient.py` pass, STL saved on its largest flat face; (2) file in `print/<part>_<version>.<ext>` and copied to `print/latest/<part>.<ext>`, `LATEST.md` line rewritten (version, date, g, sha256 first 12); (3) State READY in `current-parts.md` with the file name; (4) one line in `log.md`; (5) `runs/<part>/<version>/summary.md` written in this form, with the preview image beside it:
```
<part> <version>: ready to print
Weight: <g> (M), was <g> (+/- g)
Strength: worst index <x> in <case> (was <y>); weakest spot <where>
Solid: solid_check PASS (1 body, 1 eroded body, 0 necks, 0 thin walls)
Print: <bed face>, bed contact <mm²> (M), tree supports <g>; file <name>
```
(6) committed and pushed, PR open.

## Docs
- Live docs hold current state only. One fact, one cell: a state only in `current-parts.md`, a number only in `dimensions.md`; other docs link. A retired design is deleted, not described.
- Changing a number: its row in `dimensions.md` plus one line in `log.md`.
- Several sessions write at once: pull right before editing, change only your own rows, keep edits small.

## Git
- Commit messages: `<part> <version>: <what>` or `ckpt <n>`. Push after every commit.
- LFS tracks `*.stl *.3mf *.obj *.step *.png *.gcode *.zip`. Keep any single file under 100 MB.
- Never force-push `main`. Never rewrite history on a shared branch.
