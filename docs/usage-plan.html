Why long sessions are expensive

Every tool call re-sends the whole conversation. A 700k session pays for 700k tokens of cache read on each of its calls, so a 300-call turn costs about $34 (Overseer arms, 24 Oct 13:29, M). When the session sits idle past the 1 h cache, the next wake rewrites the whole context ($1.5-2 before it does anything). Wakes for "run still going" notices pay that same price for one line.

Where the sampled turns went (146 turns, $247, M): human-started $108 (50 turns), background-job wakes $88 (79), worker and review hand-backs $50 (17).

The plan, ranked by saving

#ChangeSaves (E)Who
1Cap context at 300k. "autoCompactWindow": "300k" in .claude/settings.json (accepted values 100k to 1M). Before a session passes it, it writes its state to the part doc and row, so a compact loses nothing. Try on one session first.30-40%config
2Orchestrators delegate the loop. CAD iterations, FE retries and fix-review cycles go to one worker (fresh context, sonnet for runs) that returns 10 lines. The orchestrator never runs a 300-call turn itself.15-25%docs
3One wake per run. A heavy run starts as one background job that commits its own checkpoints and exits only when done (a wrapper script), so the parent is woken once, not every poll. No "still waiting" turns (Scout v3: 22 wakes at 720k).10-15%tool + docs
4Organiser kept small. Every 12 h instead of 6; a cheap exit ("nothing new" in one line) when main and the sessions have not moved; the light pass runs in one sonnet worker so the organiser spends 3 calls; its context is capped by item 1. A fresh session per run was dropped: it has no repo or session tools (tested 24 Oct). A scheduled GitHub Action was dropped: it would email on every red run.~$12/dayconfig
5Sync by pull, not by push. Children already merge origin/main every step. A controller messages a child only when a change hits that child's own inputs, one message per change set, priority "later" so it rides the child's next turn instead of waking a 500k context.5-10%Spark rule
6Script the mechanical review. tools/review_precheck.py runs review items 1, 2, 5, 6, 9, 10, 11 (PASS line, row and log cells, tags, preview PNG, check_state, artifact link, carbon list). The opus reviewer is called only after it is clean and judges design only; a re-review checks only the items that failed.3-5%tool
7Model on every spawn. create_session inherits the caller's model, so heavy-run sessions ran on opus (nox topo runs, 23-24 Oct). Every heavy-run spawn passes model: sonnet; tools/check_state.py or the sweep reports an opus run session.smalldocs
8Slim what every session reads. dimensions.md is 159 KB with lines up to 5,475 chars; add tools/dim.py <section> and a check_state warning over 600 chars per line. 63 log.md lines break the 400 cap. CLAUDE.md is 11.8 KB against its own 10 KB target. Each saved KB is re-read on every call.2-4%tool

Together (E): roughly half today's spend, with no change to the design rules or the gate. Items 1, 4 and 7 can land today; 5 changes a Spark rule ("Children stay in sync").

Not proposed

  • Dropping the review agent, the solid gate, the visuals or opus on design work: they are Spark's rules and the cost is in context size, not in them.
  • Fewer parallel sessions: parallel is fine; the cost is each session's context, not their count.
