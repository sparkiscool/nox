# Nox print log

Every print job, newest first. Rule (Spark, 5 Oct 13:47): add a row the moment Spark tells a session to print a part, or a job is sent from Bambu Studio to the printer. Sent counts as printed. A failed or cancelled print gets its own new row, the old row stays. Re-read right before writing; add rows only at the top.

**All prints go through a chat using computer control (Spark, 5 Oct 13:49).** The session that clicks send in Bambu Studio writes the row in the same turn, before it replies. No print is sent any other way, so a missing row means a session skipped the rule.

**One Bambu Studio window per print (Spark, 11 Oct 13:56; 17 Oct 15:34):** never launch Bambu Studio while it is running (an "open app" call starts a second copy; 9 piled up on 17 Oct): click the open window instead. Before opening or slicing the next print, close every other Bambu Studio project window / print tab (save first if unsaved), so only the job being sent is open. Several open projects crashed the PC on 11 Oct.

**Supports on every part (Spark, 17 Oct 16:36):** tree(auto), enabled globally, none switched off per object. Rule in `docs/generative.md`.

**Remote typing (18 Oct 01:25, 01:37, 05:13):** the remote "type" action pastes through the shared clipboard, so a path typed into a Bambu dialog can come out as whatever Spark last copied. Backslash paths fail most often; a bare file name (dialog already in the right folder) or forward slashes go through. Zoom on the file name field before every Enter; one bad name was caught twice that night and twice more on the 18th.

**SD card I/O errors (17 Oct 16:34, 22:46; 18 Oct 02:28, 02:39, 05:14, 05:17):** a freshly inserted card often shows F: with "I/O device error" and is missing from This PC until it is re-seated; when Windows pops an Explorer window for it, the card is readable. If the Explorer window steals the front, click into the Bambu dialog's File name box to get back (never `open_application`).

**Arrange spacing (18 Oct 04:53):** Bambu's default arrange packed the seat pads so close that their 60° flares crossed at layer 10 (slicer "conflicts of gcode paths"). Re-arrange, or lay out the plate in a geometry-only 3mf, and check the slicer warning before exporting.
